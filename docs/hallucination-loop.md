# whisper 환각 루프: 에러 없이 망가지는 전사

## 증상

38분짜리 회의 녹음을 넣었는데 회의록에 회의 맨 앞부분 얘기만 나왔다. 스크립트는 에러 없이 끝났다.

## 단계별로 나눠서 확인

어느 단계에서 깨지는지 하나씩 떼어 확인했다.

| 확인 | 결과 |
|---|---|
| 원본 파일 재생 | 정상 |
| ffmpeg 변환 결과 | 정상 |
| 5분 단위로 잘라서 전사 | 정상 |
| 전체 파일 전사 | **실패** |

잘라서 넣으면 되는데 전체로 넣으면 안 됐다. 전체 전사 결과를 열어 보니 같은 문장이 **2,146줄** 반복돼 있었다. 회의 시작 전 무음 구간에서 whisper가 문장 하나를 만들어 냈고, 그 문장을 다음 구간의 문맥으로 계속 물고 가면서 뒤쪽 전체가 같은 문장으로 덮였다.

## 수정

whisper.cpp의 `-mc 0`(max-context 0) 옵션으로 이전 구간의 텍스트를 다음 구간에 넘기지 않게 했다. 같은 녹음이 424줄의 정상 전사로 나왔다.

## 재발 방지

고친 것보다 **에러 없이 망가졌다**는 점이 더 문제였다. 다음에 다른 원인으로 같은 일이 생겨도 알아챌 수 있게 두 가지를 넣었다.

1. **whisper 로그 보존**: 전에는 stderr를 `/dev/null`로 버리고 있었다. 지금은 실행마다 `.logs/<시각>_whisper.log`로 남긴다.
2. **반복 감지**: 전사의 고유 줄 비율을 계산해 20% 이하면 경고하고 원문을 백업한다.

### 감지 로직은 실패 사례로 검증해야 한다

처음 만든 감지는 "고유 줄이 3줄 이하면 경고"였다. 실제 실패 전사에 돌려 보니 **잡지 못했다.** 반복 문장에 미세한 변주(조사, 띄어쓰기 차이)가 섞여 고유 줄이 12줄이었기 때문이다.

그래서 개수 대신 비율로 바꿨다. 정상 회의 전사는 고유 줄 비율이 95% 이상이고, 환각 루프는 이 비율이 급락한다. 30줄 미만의 짧은 전사는 비율이 흔들려서 검사하지 않는다.

`tests/run.sh`에는 이 경우를 재현하는 테스트(미세 변주가 섞인 반복 전사)가 들어 있다.

```sh
sh scripts/meeting-notes.sh --check-transcript <전사.txt>   # 0 정상, 2 반복 의심
```
